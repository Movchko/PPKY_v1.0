# Тексты UI ППКУ и события, которые их вызывают

Документ собран по коду `TouchGFX/gui`, `Core/Src/fire.c`, `Core/Src/warning.cpp`.
Покрывает **динамические строки** (формируются в приложении) и **пункты меню** (TypedText / хардкод).
Подписи кнопок на лицевой панели (ПУСК СП, ПУСК ОБЩИЙ и т.п.), если они нарисованы как картинки без текста в коде, здесь не перечисляются.

Зоны отображения на **главном экране** (`mainscreen`):

| Поле | Виджет | Назначение |
|---|---|---|
| Верхний заголовок | `textAreatime_top_bar` | «ДО ПУСКА» / «ПАУЗА» / «АВАРИЯ n/m» / «ВНИМАНИЕ» |
| Большое поле | `textArea1` | статус пожара/тушения **или** заголовок неисправности |
| Бегущая строка | `CustomContainerSrollText` | имя зоны **или** деталь неисправности |
| Время/дата | `CustomContainerScrollTime1` | штатный режим без аварии/пожара |

Приоритет баннеров: **пожар перекрывает предупреждения**. Пока `fireUiActive`, warning-баннер не обновляется.

## 1. Главный экран — пожар / тушение

Источник: `Fire_UpdateUiText()` → `Fire_UiUpdate()` → `Model::setFireStatusFromApp()` → `mainscreenView::updateFireStatus()`.

Параметр `mode` (ui_mode) задаётся в `fire.c` по состоянию FSM.

### 1.1. Большое поле (`textArea1`)

| Текст | `mode` | Когда появляется |
|---|---:|---|
| `NС` (например `12С`) | `1` | Ожидание пуска: идёт отсчёт zone_delay («ДО ПУСКА»). Также при удержании «ПУСК ОБЩИЙ» 3 с без активного пожара |
| `NС` | `5` | То же ожидание, но таймер **на паузе** (`PauseExtinguishmentTimer` / концевик Pause) |
| `ПОЖАР1` | `6` | Зона в режиме «И»: принят первый источник пожара, ждём второй (fire1_waiting) |
| `ТУШЕНИЕ` | `2` | Состояние `FIRE_STATE_EXTINGUISHING`, фаза 2 запущена, end_ack ещё не по всем спичкам |
| `ТУШ.ВЫП.` | `3` | Все активные зоны получили end_ack спичек (тушение произведено) |
| `ТУШ.ОШ.` | `7` | Тушение завершилось с ошибкой (исчерпаны retry, не все end_ack) |
| `ПОЖАР/ОСТ.` | `4` | Нажат «ОСТАНОВ ПУСКА» / countdown остановлен; слоты пожара сохранены |
| `N` (число без «С») | иное + `remaining_s>0` | Запасной формат таймера |
| *(пусто)* | — | Нет пожара / нет активного сценария |

### 1.2. Верхний заголовок (`textAreatime_top_bar`)

| Текст | Условие |
|---|---|
| `ДО ПУСКА` | `mode == 1` (ожидание пуска) |
| `ПАУЗА` | `mode == 5` (пауза отсчёта) |
| *(пусто, но шапка видна)* | `mode == 6` (ПОЖАР1) |
| *(скрыт, показывается время)* | остальные режимы / нет пожара |

### 1.3. Бегущая строка (имена зон)

| Текст | Событие |
|---|---|
| Имя зоны из `PPKYConfig.zone_name[zone-1]` | Активен слот пожара / тушения по этой зоне |
| *(пусто)* | Нет активных зон в UI-списке |

Список зон обновляется при:

- `SetStatusFire` от ДПТ / кнопки Fire* → `Fire_OnStatusFire` → новый слот зоны;
- `ПУСК ОБЩИЙ` / внешняя кнопка Start* → слоты зон тушения;
- ротация зон каждые ~3 с (или по UP/DOWN в ручном выборе).

### 1.4. События FSM → смена режима UI

| Событие | Код / вход | Типичный `mode` после |
|---|---|---|
| Пожар от ДПТ / кнопки FireAll/FireZone | `ServiceCmd_Fire_SetStatusFire` (`source=sensor`) | `1` или `6` (ПОЖАР1 при AND) |
| Автопуск по истечении zone_delay | `Fire_ProcessAutoDeadlines` | `2` |
| ПУСК СП (кнопка / вирт. StartSP) | `FIRE_EVENT_BTN_START_SP` / `StartSpButton(163)` | `2` |
| ПУСК ОБЩИЙ (удержание 3 с) | `FIRE_EVENT_BTN_START_ALL` | `2` (+ перед этим SetStatusFire source=PPKU) |
| Внешняя кнопка StartAll/StartZone | `StartExtinguishment` + SetStatusFire source=button | `2` (UI слоты), без FSM-пожара от датчика |
| Пауза таймера | `PauseExtinguishmentTimer` / концевик Pause | `5` |
| Возобновление | `ResumeExtinguishmentTimer` | `1` |
| ОСТАНОВ ПУСКА | кнопка STOP | `4` |
| Все спички end_ack | статусы IGNITER | `3` |
| Ошибка дотушивания | retry исчерпаны | `7` |
| Удержание ПУСК ОБЩИЙ без пожара | кнопка START_ALL press | `1` + таймер 3→0, без имён зон |

## 2. Главный экран — предупреждения / аварии

Источник: `warning.cpp` → `Warning_UiUpdate()` → `Model::setWarningStatusFromApp()` → `mainscreenView::updateWarningStatus()`.

Показывается **только если нет активного пожарного баннера**.

### 2.1. Верхний заголовок

| Текст | Условие |
|---|---|
| `ВНИМАНИЕ` | Текущий элемент списка — attention (`ОТКРЫТИЕ` / `ТЕМП.`) |
| `АВАРИЯ n/m` | Обычная неисправность; `n` — индекс, `m` — всего |

### 2.2. Большое поле + бегущая строка

| Большое поле | Бегущая строка (деталь) | Kind / условие | Событие появления |
|---|---|---|---|
| `ОТКРЫТИЕ` | `{имя_зоны} {MKU Kx} {h_adr} S/N:...` | `WARN_KIND_LSWITCH_OPEN_ATTN` | Концевик: `line_state=4` (открытие) |
| `ТЕМП. {t}` | то же | `WARN_KIND_DPT_WARNING_ATTN` | ДПТ: `status_cmd = Warning`, `t` = температура MAX |
| `ВЫХОД 1` / `ВЫХОД 2` | `ППКУ S/N:...` | power out fault | Неисправность выхода питания МКУ (канал 1/2) |
| `ПИТАНИЕ 1` / `ПИТАНИЕ 2` | `ППКУ S/N:...` | input power fault | Неисправность входа питания ППКУ |
| `ОБРЫВ ДПТ{n}` / `КЗ ДПТ{n}` / `НЕИСП ДПТ{n}` | `{зона} {MKU..} {h} S/N:...` | `WARN_KIND_VDEV_FAULT` | ДПТ: line_state 1/2/5 |
| `ОБРЫВ СП{n}` / `КЗ СП{n}` / `НЕИСП СП{n}` | то же | `WARN_KIND_VDEV_FAULT` | Спичка (IGNITER): обрыв/КЗ/неиспр. |
| `ОБРЫВ КОН{n}` / `КЗ КОН{n}` / `НЕИСП КОН{n}` | то же | `WARN_KIND_VDEV_FAULT` | Концевик: обрыв/КЗ/неиспр. |
| `ОБРЫВ КН{n}` / … | то же | `WARN_KIND_VDEV_FAULT` | Кнопка (если трекается как fault) |
| `ОБРЫВ CAN0` / `ОБРЫВ CAN1` / `КЗ CANx` | `{зона} {MKU..} …` | `WARN_KIND_MCU_CAN_FAULT` | Статус МКУ: неисправность линии CAN |
| `ПОЗИЦИЯ` | `МКУ {h_adr}` | `WARN_KIND_MCU_POSITION_FAULT` | Ошибка позиционирования МКУ в кольце |
| `ОТСУСТВ.` | `{зона} {MKU..} {h} S/N:...` | `WARN_KIND_DEVICE_MISSING` | МКУ/канал из конфига не online (`config_monitor`) |
| `НОВОЕ` | `{зона} {MKU..} {h} S/N:...` | `WARN_KIND_DEVICE_FOUND` | Online устройство/канал не в конфиге; S/N с удалённой МКУ |
| `ОШ. КОНФ.` | `{зона} {MKU..} {h} S/N:...` | `WARN_KIND_CONFIG_MISMATCH` | CRC MKUCfg ≠ образ в PPKYConfig |
| `ОБРЫВ CAN0` / `ОБРЫВ CAN1` | `ППКУ S/N:...` | `WARN_KIND_PPKU_CAN_FAULT` | Обрыв CAN на стороне ППКУ |

Сокращения типов канала: `ДПТ`, `СП`, `КН`, `КОН`.  
Типы МКУ в детали: `MKU K1` / `MKU K2` / `MKU K3` / `MKU KR` / `MKU IGN` / `MKU TC`.  
Если имя зоны пустое в конфиге → `ЗОНА N`.

### 2.3. События, наполняющие список

| Событие | Откуда |
|---|---|
| Смена статуса виртуального устройства | статусы МКУ по CAN → `UpdateActiveVirtualDevices` → `ConsumeChangedStatuses` |
| CAN МКУ КЗ/обрыв | `can_state_mask` в heartbeat МКУ |
| CAN ППКУ обрыв | диагностика шин ППКУ |
| Ошибка позиции | `Warning_SetMkuPositionFaultMask` |
| Сверка конфига с шиной | `ConfigMonitor_Process1ms` → `SyncConfigMonitorItems` (события лога 4/5/6) |
| Ошибка выхода питания | `Warning_SetPowerFaultMask` из `App_UpdatePowerFaultIndication` |
| Ошибка входа питания | `Warning_SetPpkuInputFaultMask` |
| Восстановление | `MarkRecovered` / prune; строка может держаться ещё ~10 с (`WARNING_SHOW_HOLD_MS`) |

Ротация строк: ~3 с на элемент (или после полного прохода бегущей строки).  
UP/DOWN — ручной выбор; ESC / таймаут — авторотация.

## 3. Главное меню (`ScreenMenu` + `mainmenu`)

| Текст | Источник | Когда |
|---|---|---|
| `Режим` | TypedText `T_MODE` | Пункт меню index 0 |
| `Звук` | `T_SOUND` | index 1 |
| `Связь` | `T_CONNECT` | index 2 |
| `Журнал` | `T_JURNAL` | index 3 |
| `Устройства` | `T_DEVICES` | index 4 |
| `Тест` | `T_TEST` | index 5 |
| `Автоматический` | хардкод | Режим пожара `fire_mode==0` |
| `Автономный` | хардкод | `fire_mode==1` |
| `Ручной` | хардкод | `fire_mode==2` |
| `Вкл` / `Откл` | хардкод | Состояние звука |
| `Вкл БЛОК.` / `Откл БЛОК.` | хардкод | Звук при блокировке бипера |

Смена режима: кнопка в меню режима (циклическое переключение `fire_mode`).  
Смена звука: пункт «Звук».

## 6. Экран «Устройства» (`screen_devices`)

|---|---|
| `{имя зоны}` или `Зона N` | Есть МКУ в `PPKYConfig` |
| `МКУ К1:h` / `К2` / `К3` / `КР` / `ТС` / `ИГН` | Текущий выбранный МКУ |
| `МКУ …:h` (Далее) | Следующий МКУ в списке |
| `Нет МКУ в конфигурации` | Список пуст |
| `МКУ: -` / `Далее: -` | Список пуст |
