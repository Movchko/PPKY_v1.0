# Методика и протокол функциональных испытаний ППКПиУ

**Область:** звуковая/световая индикация, алгоритм управления тушением, обработка пожара, журналирование событий  
**Нормативная база:**
- `Требования_к_ППКПиУ_в_части_индикации_и_алгоритма_управления_тушением.md` (далее — Тр.)
- `7 раздел. ГОСТ 53325.md` (п. 7.2–7.6 в части, относящейся к объекту)
- Внутреннее описание режимов: `режимы индикации.md`, `ЛОГЕР_СОБЫТИЙ.md`

**Объект:** ППКУ (`stm_PPKY`) + МКУ/устройства на CAN (при необходимости имитаторы)  
**Дата сверки с ПО:** 2026-07-15 (обновлено по ответам заказчика)  
**Правки в код по итогам не вносятся** — документ для приёмки и планирования доработок.

## 0. Принятые решения (по ответам 2026-07-15)

| Тема | Решение |
|------|---------|
| Критерий приёмки | **Строго** Тр. + ГОСТ. Расхождения устраняются в ПО **или** согласуется трактовка письменно. |
| Частоты `LED_FIRE` (ВНИМАНИЕ / ПОЖАР1 / ПОЖАР2) | Доработка **в работе у разработчика**. Агент не правит; повторная сверка после готовности. |
| Задержка ≥30 с, шаг ≤10 с (Тр. 4.10) | Ограничение в **внешнем конфигураторе** (ПО верхнего уровня), не в firmware ППКУ. В протоколе проверять на корректном конфиге. |
| Сброс ПОЖАР (ГОСТ 7.3.1е) | Требуется. Планируется: под `#define` тестирования ГОСТ — удержание **ОСТАНОВ ПУСКА ≥3 с** → сброс пожара. |
| УДП (4.7–4.8) | **Есть:** кнопка на CAN-шине. Режимы: как ПУСК СП своей зоны / как ПУСК ОБЩИЙ / пуск выбранных зон из списка. Закрывает Тр. 4.7–4.8 (оба способа ручного пуска). |
| Выходы ПУСК / НЕИСПРАВНОСТЬ | **Согласованная трактовка:** реле mode «Пожар» = выход **Пожар** и **Пуск** (срабатывание по пожару). Режим реле «Неисправность» = выход **Неисправность**. |
| дБ(А) (3.13) | Внешний шумомер; в этой методике не акцент — одна строка «измерение лабораторией». |
| «ОТКЛЮЧЕНИЕ» (7.2.13) | См. §9. Если функция временного вывода зон/адресов **не заявляется** — индикатор «ОТКЛЮЧЕНИЕ» по ГОСТ не обязателен. |
| ТЕСТ (3.20–3.21) | Стартовый прогон индикации при включении **можно зачесть** частично. Полный ТЕСТ — пункт меню под `#define` ГОСТ-тестов. |
| `fire_mode=1` (автономный) | **Внутренний** режим изделия; к классификации ГОСТ авто/ручной/блокировка **не относится**. В ГОСТ-протоколе проверять `0` и `2`. |
| `режимы индикации.md` vs код | Полная построчная сверка обязательна (отдельный проход). |

**`#define` ГОСТ-тестов:** в коде `stm_PPKY` на момент сверки **отдельного макроса не найдено**. Нужно ввести (имя зафиксировать в ТД/сборке), например `PPKY_GOST_TEST_FEATURES`, и под ним: сброс пожара удержанием СТОП 3 с; пункт меню ТЕСТ.

## 1. Цель и объём

1. Проверить выполнимость требований Тр. п. 3–5 и связанных пунктов ГОСТ 53325 (7.2.4, 7.2.8, 7.2.13, 7.3.1–7.3.3, 7.4, 7.5, 7.6) средствами имитации событий и контроля индикации/выходов/логов.
2. Зафиксировать соответствие текущей реализации (статус **С / ЧС / НС / Н/П**):
   - **С** — соответствует (по коду/документации);
   - **ЧС** — частично соответствует;
   - **НС** — не соответствует;
   - **Н/П** — не применимо к текущей конфигурации / требует измерения на стенде / нет данных.

### Ограничения объёма методики

| Включено | Исключено (отдельные виды испытаний) |
|----------|--------------------------------------|
| Функциональная логика индикации, звука, пожара, тушения, логов | Климатика, вибрация, ЭМС, изоляция (ГОСТ 7.7–7.8, 7.10.3, 7.16.4–9) |
| Временные параметры реакции (секундомер / лог) | Детальная акустика дБ(А) — внешний шумомер, одна отметка в протоколе |
| Архив событий ≥1024, FIFO, отсутствие delete | Удаление архива предприятием-изготовителем (аппаратный доступ) |
| Режим автономный (`fire_mode=1`) | Не входит в ГОСТ-матрицу авто/ручной/блокировка |

## 5. Методика (общие правила)

1. Имитировать входное событие → наблюдать LED, звук, СОТИ, реле/выходы, запись в лог (выгрузка протокола чтения).
2. Время реакции: от момента события (CAN/кнопка/обрыв) до устойчивого состояния индикации/выхода.
3. Частота мигания \(f = 1/T\), где \(T\) — период «вкл+выкл»; измерить не менее 10 периодов.
4. Уровень звука: 1 м по оси излучателя, фон ≤ фоновой нормы лаборатории; серия измерений для ПОЖАР, ПУСК, НЕИСПРАВНОСТЬ.
5. При конфликте требований «документ режимов индикации» vs Тр./ГОСТ — **критерий приёмки = Тр. + ГОСТ**; внутренний `режимы индикации.md` — справочно.
6. Критерий годности секции: все пункты секции **С** или допустимые **Н/П** с пометкой; любой **НС** по критическим пунктам (3.3, 3.12, 3.16, 4.15, 7.2.4, отсутствие автоотключения ПОЖАР) — рекламация.

## 6. Протокол испытаний (формы)

Заполняется на стенде. Колонки: **№ п/п | Шаг | Ожидание (норма) | Факт | Время/изм. | Соотв. (да/нет) | Примечание**.

### Секция A — Дежурный режим и питание

| ID | Шаг | Ожидание | Соотв. коду (сверено) |
|----|-----|----------|------------------------|
| A1 | Включение, оба ввода в норме | `LED_POWER` ON, `LED_NORM` ON, без звука тревоги | С |
| A2 | Пропадание/снижение одного ввода | Свет/звук НЕИСПРАВНОСТЬ ≤300 с; индикация питания | ЧС — проверить LED_POWER (гаснет) и fault |
| A3 | Восстановление ввода | Возврат без ложных ПОЖАР/ПУСК | На стенде |
| A4 | Лог после boot | События запуска мастера/системы | С (коды 1–3 частично) |

### Секция B — Цвета и обобщённые индикаторы

| ID | Шаг | Ожидание |
|----|-----|----------|
| B1 | ПОЖАР2 | Красный `LED_FIRE` непрерывно |
| B2 | ПУСК | Красный `LED_START` (режим по Тр. — непрерывно; факт — мигание+hold) |
| B3 | НЕИСПРАВНОСТЬ | Жёлтый `LED_ERR` |
| B4 | АВТОМАТ ОТКЛ. | Жёлтый `LED_AUTO_OFF` непрерывно |
| B5 | ОСТАНОВ ПУСКА | Жёлтый `LED_STOP` |
| B6 | ПИТАНИЕ / НОРМА | Зелёные индикаторы |

## 9. Пояснения и оставшиеся вопросы

### 9.1 УДП (закрыто)

**УДП** = кнопка на CAN-шине. Режимы конфигурации:
1. как **ПУСК СП** своей зоны;
2. как **ПУСК ОБЩИЙ**;
3. пуск тушения **выбранных зон из списка**.

Вместе с органами ППКУ закрывает Тр. 4.7–4.8. В протоколе: G13–G15. Внешний вид УДП (не красный, надпись) — ГОСТ 7.4.6, конструктивная проверка отдельно.

### 9.2 Выходы ПУСК / НЕИСПРАВНОСТЬ (закрыто трактовкой)

| Требование ГОСТ/Тр. | Реализация |
|---------------------|------------|
| Выход **Пожар** | Реле mode «Пожар» (срабатывание по пожару) |
| Выход **Пуск** | То же реле / тот же mode «Пожар» |
| Выход **Неисправность** | Реле mode «Неисправность» |

Зафиксировать формулировку в ТД. На стенде: G11–G12, активация ≤10 с.

### 9.3 Что такое «ОТКЛЮЧЕНИЕ» (вопрос 8)

Это не «автоматика отключена» и не «звук отключён».

По ГОСТ 7.2.13 / 7.6.1.18: оператор **временно выводит из работы** отдельный вход/зону/адрес/шлейф (ремонт, ложные срабатывания). Требования:
- индикация «ОТКЛЮЧЕНИЕ» (жёлтый);
- расшифровка что отключено;
- прибор **не принимает** сигналы от отключённого;
- событие в архив.

Если такая функция **не заявляется** в ТД — отдельный индикатор и испытания по 7.2.13 не нужны. Текущее решение: **не заявляем** → в матрице **Н/П**.

### 9.4 Открытые вопросы

1. Имя и место `#define` ГОСТ-тестов (в коде пока нет)?
2. Блокировка пуска по направлению (Тр. 4.9.3): доработка или трактовка «только глобальный ручной»?
3. Mute: LED «ЗВУК ОТКЛ.» + автовозобновление — устраняем или трактовка?
4. После готовности частот `LED_FIRE` — повторная сверка секции C.
5. Построчная сверка `режимы индикации.md` ↔ код — следующим шагом?
