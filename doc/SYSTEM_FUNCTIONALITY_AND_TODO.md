
## АЦП и фильтрация

- **Текущая реализация**: SMA (скользящее среднее) в `adc.c` (stm_PPKY, MCU_TC, MCU_igniter_v03).
- **Требование**: добавить **параметр измерения СКО (стандартное отклонение)** по каждому каналу для валидации.
- **Результат**: флаг **достоверности** по каждому каналу (значение валидно / невалидно).
- **Местоположение**: `adc.c` во всех проектах с АЦП.

---

##  ППКУ: хранение и проверка настроек МКУ

- ППКУ хранит настройки всех МКУ.
- При запуске: считывает настройки (или контрольную сумму) и **сравнивает**.
- Если настройки **отличаются** — сообщить определённым **флагом**.
- Далее — функционал логирования и конфигурирования.

---

## Силовой ключ питания (BTS740S2)

- **Текущая реализация**: `PControl` в `stm_PPKY`, GPIO ST/OUT, без прерывания по статусу.
- **Сигнал ST (GPIO)**:
  - **ST = 1**: питание выключено, либо КЗ/неисправность.
  - **ST = 0**: питание включено и всё в норме.
- **Требование**:
  1. Настроить **прерывание на ST** (по фронту/уровню при переходе в 1).
  2. При ST = 1 при включённом питании — **сразу отключать** выход.
  3. Пытаться **повторно включить** через N мс (пока 2), до M попыток (пока 1 с).
  4. После неудачи — выставить **флаг ошибки питания**.
- **Местоположение**: `stm_PPKY/Core` (power_control, main, прерывания).

## Настройки ППКУ

- **Выбор питания**: список 0, 1, 2.
- **Наличие БРП**: 0 или 1.
- **Местоположение**: `PPKYCfg` в `device_config.h`, конфигурация ППКУ.

- **Мелкие**: LED_BUT_ENTER_UP (13), LED_BUT_ESC_DW (14)

### Backend

- Реализованы команды ПОЖАР и ответ на ПОЖАР на базе существующих вызовов `SetStatusFire`, `SetReplyStatusFire`, `RcvStatusFire`, `RcvReplyStatusFire` и сервисных команд backend (задача 1).
- Добавлены команды задания адресов по кольцу: `ServiceCmd_CircSetAdr` и `ServiceCmd_StopStartReTranslate` (задача 3).
- Реализован кольцевой алгоритм нумерации МКУ:
  - ППКУ запускает механизм через команду 10 (CommandCB в ППКУ) по CAN0;
  - МКУ по кольцу обрабатывают `ServiceCmd_CircSetAdr`, устанавливая себе адреса и передавая команду дальше;
  - после завершения ППКУ перезапускает питание линий и обновляет список активных устройств (задача 4).
- В backend добавлена команда `ServiceCmd_SaveSystemConfig` для последующей реализации сохранения конфигурации системы в ППКУ (часть задачи 5).
